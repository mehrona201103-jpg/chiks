# ✦ Chikstagram

**TikTok + Telegram в одном приложении.** Короткие видео с вертикальной лентой, лайки, комментарии, репосты и подписки — плюс личные сообщения, группы, публичные каналы, файлы и голосовые. Классическая чёрно-оранжевая тема, адаптив под телефон и компьютер.

Полностью бесплатный стек, **ноль внешних зависимостей** (никаких `npm install`):

| Слой | Технология |
|---|---|
| Сервер | Node.js ≥ 22.5, встроенный `http` |
| База данных | SQLite (встроенный `node:sqlite`), файл `data/chikstagram.db` |
| Realtime | Server-Sent Events (сообщения, уведомления, «печатает…») |
| Frontend | Чистый HTML/CSS/JS (SPA на hash-роутере), без сборки |
| Видео | Отдача с Range-запросами (перемотка), превью через `ffmpeg` (необязательно) |
| Безопасность | scrypt-хеши паролей, токены сеансов, rate-limit, CSP, проверка форматов файлов |

## Запуск

```bash
npm start            # http://localhost:3000
```

Демо-аккаунты и демо-видео **отключены**. Приложение стартует с пустой базой — только реальные регистрации. Для демо-контента: `CHIK_SEED=1 npm start`.

Переменные окружения: `PORT` (3000), `CHIK_DATA` (папка данных), `CHIK_SEED=1` (создать демо-данные).
Демо-видео генерирует `ffmpeg`; если его нет — стартует пустая лента, а свои файлы загружаются как обычно.

```bash
npm test             # 82 интеграционных проверок API на временной БД
npm run seed         # наполнить пустую БД демо-данными
```

## Возможности

1. **Аккаунты** — регистрация, вход по нику/email, профиль (аватар, имя, bio), сеансы на устройствах, смена пароля, удаление аккаунта.
2. **Лента** — вертикальный scroll-snap, автоплей видимого видео, тап = пауза, двойной тап = лайк, звук, клавиши `↑ ↓ L M Space`, вкладки «Для вас» / «Подписки», бесконечная подгрузка.
3. **Загрузка** — видео (mp4/webm/mov) и фото (jpg/png/webp/gif) **до 5 ГБ** без перекодирования (качество и звук сохраняются). Загрузка **потоковая** — файл сразу пишется на диск, без удержания в RAM. Drag-and-drop, прогресс, подпись с #хештегами и @упоминаниями. После загрузки публикация сразу видна.
4. **Соцвзаимодействие** — лайки, комментарии (удаление), репосты на профиль и в чат, закладки, подписки, заявки в закрытые аккаунты.
5. **Мессенджер** — личные чаты, группы, публичные каналы; фото, видео, файлы, голосовые сообщения, эмодзи, ответы, удаление, «печатает…», непрочитанные, отправка постов в чат.
6. **Роли** — владелец / админ / участник; в канале пишут только админы; ссылки `#/c/handle`.
7. **Поиск** — люди, видео, каналы, группы, хештеги; тренды и обзор публичных чатов.
8. **Уведомления и рекомендации** — лайки, комментарии, подписки, репосты, упоминания (в реальном времени); лента ранжируется по свежести, вовлечённости и вашим интересам (хештеги понравившегося).
9. **Приватность** — закрытый аккаунт, скрытие статуса «в сети» и лайков, кто может писать / комментировать, чёрный список, жалобы, завершение чужих сеансов.
10. **Дизайн** — классическая чёрно-оранжевая тема, сдержанные цвета, плавные анимации, адаптив (сайдбар на ПК → нижняя навигация на телефоне).
11. **Из TikTok:** комментарии с ответами и лайками, скачивание видео, «Поделиться» через системное меню телефона.
12. **Из Telegram:** реакции на сообщения, редактирование («изм.»), закреплённые сообщения и чаты, пересылка, поиск по чату, статус «прочитано» ✓✓.

## Структура

```
server/
  index.js     HTTP-сервер, статика, отдача медиа (Range), SSE-поток
  api.js       REST API (auth, посты, чаты, поиск, уведомления, приватность)
  db.js        схема SQLite и хелперы
  util.js      хеши, multipart-парсер, загрузка файлов, rate-limit
  realtime.js  SSE-хаб
  seed.js      демо-данные (видео генерируются ffmpeg)
  test.js      интеграционные тесты
public/
  index.html · css/app.css · js/{core,feed,chat,pages,main}.js
data/          БД и загруженные файлы (создаётся автоматически)
```

## Деплой бесплатно

Любой бесплатный хостинг с Node 22+ и постоянным диском (Fly.io, Render, Railway, свой VPS): `npm start`, смонтируйте `CHIK_DATA` на постоянный том. За reverse-proxy (nginx/Caddy) включите HTTPS. Для загрузки до 5 ГБ в nginx: `client_max_body_size 5G;` и увеличьте `proxy_read_timeout` / `proxy_send_timeout` (например 3600s). На сервере желательно ≥8 ГБ RAM.

## Ограничения MVP

SQLite и SSE рассчитаны на один сервер. Для масштаба: вынести файлы в S3-совместимое хранилище, БД — в PostgreSQL, SSE — на Redis pub/sub. Нет e-mail-подтверждения и восстановления пароля (нужен почтовый сервис).


## Chikstagram V2 — вход и регистрация

- Регистрация: имя латиницей, уникальный никнейм (3–24 символа), email и пароль.
- Никнейм проверяется на занятость до отправки формы; `@` показывается автоматически.
- Пароль: минимум 8 символов, заглавная и строчная латинские буквы и цифра.
- Вход по никнейму или email.
- Сессия хранится в браузере; пользователь остаётся авторизованным до выхода или очистки данных браузера.
- Google Sign-In поддерживается после настройки OAuth Client ID.

### Как включить вход через Google

1. Откройте https://console.cloud.google.com/ и создайте проект Google Cloud.
2. В разделе **APIs & Services → OAuth consent screen** настройте экран согласия (External, если вход для всех пользователей). Добавьте домен приложения в Authorized domains.
3. В **APIs & Services → Credentials → Create credentials → OAuth client ID** выберите **Web application**.
4. В **Authorized JavaScript origins** добавьте адрес сайта, например `https://chik-wsyy.onrender.com` (без `/` в конце).
5. Скопируйте Client ID. Client secret для этого Google Identity Services flow не нужен.
6. В панели хостинга добавьте переменную окружения `GOOGLE_CLIENT_ID` со значением Client ID и перезапустите приложение.
7. В Google OAuth consent screen добавьте тестовых пользователей, пока приложение находится в режиме Testing. Для публичного запуска завершите публикацию/верификацию по требованиям Google.

Сервер проверяет Google ID token на стороне сервера, сверяет аудиторию с `GOOGLE_CLIENT_ID` и требует подтверждённый Google email. Существующий аккаунт с тем же email связывается с Google при первом успешном входе.

**Важно:** Google OAuth невозможно полноценно проверить без Client ID и домена владельца. Не публикуйте Client Secret и не вставляйте его в frontend.
